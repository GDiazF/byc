CAMBIO 5: MEDIA FILES (Almacenamiento de archivos subidos)
----------------------------------------------------------
LOCAL (Sistema de archivos local):
    # Comentar o eliminar toda la configuración de AWS S3:
    # AWS_ACCESS_KEY_ID = ...
    # AWS_SECRET_ACCESS_KEY = ...
    # etc.
    
    # Habilitar estas líneas:
    MEDIA_ROOT = os.path.join(BASE_DIR, 'Documentacion_Personal')
    MEDIA_URL = '/media/'
    DEFAULT_FILE_STORAGE = 'django.core.files.storage.FileSystemStorage'

NUBE (AWS S3):
    # Configuración de AWS S3
    AWS_ACCESS_KEY_ID = os.environ.get('AWS_ACCESS_KEY_ID')
    AWS_SECRET_ACCESS_KEY = os.environ.get('AWS_SECRET_ACCESS_KEY')
    AWS_STORAGE_BUCKET_NAME = os.environ.get('AWS_STORAGE_BUCKET_NAME', 'byc-documentos-bucket')
    AWS_S3_REGION_NAME = os.environ.get('AWS_S3_REGION_NAME', 'us-east-1')
    AWS_S3_CUSTOM_DOMAIN = f'{AWS_STORAGE_BUCKET_NAME}.s3.amazonaws.com'
    AWS_DEFAULT_ACL = None
    AWS_S3_OBJECT_PARAMETERS = {
        'CacheControl': 'max-age=86400',
    }
    
    # Media files configuration for S3
    DEFAULT_FILE_STORAGE = 'storages.backends.s3boto3.S3Boto3Storage'
    MEDIA_URL = f'https://{AWS_S3_CUSTOM_DOMAIN}/'
    
    # Comentar estas líneas:
    # MEDIA_ROOT = os.path.join(BASE_DIR, 'Documentacion_Personal')
    # MEDIA_URL = '/media/'

NUBE: No es necesario, S3 maneja los archivos media

================================================================================
ARCHIVO: rrhh_personal/models.py
================================================================================

En los campos FileField que usan storage personalizado:

LOCAL: Usar FileSystemStorage o comentar el parámetro storage

    from django.core.files.storage import FileSystemStorage
    
    # Opción 1: Usar FileSystemStorage
    documento = models.FileField(
        upload_to=ruta_archivo,
        storage=FileSystemStorage(),
        ...
    )
    
    # Opción 2: Eliminar el parámetro storage (usará DEFAULT_FILE_STORAGE)
    documento = models.FileField(
        upload_to=ruta_archivo,
        ...
    )

NUBE: Usar OverwriteStorage (que hereda de MediaS3Storage)

    from .storage import OverwriteStorage
    
    documento = models.FileField(
        upload_to=ruta_archivo,
        storage=OverwriteStorage(),
        ...
    )

================================================================================
PASOS PARA CAMBIAR DE LOCAL A NUBE
================================================================================

1. CÓDIGO:
   - Aplicar todos los cambios mencionados arriba en settings.py
   - Verificar que 'storages' esté en INSTALLED_APPS
   - Actualizar modelos para usar OverwriteStorage()
   - Remover configuración de media en urls.py si la agregaste

2. BASE DE DATOS:
   - Hacer backup de tu base de datos local si es necesario
   - Asegurarse de que las migraciones estén aplicadas en RDS
   - Verificar conectividad con la base de datos RDS

3. VARIABLES DE ENTORNO:
   - Configurar las variables de entorno de AWS en el servidor:
     * AWS_ACCESS_KEY_ID
     * AWS_SECRET_ACCESS_KEY
     * AWS_STORAGE_BUCKET_NAME
     * AWS_S3_REGION_NAME

4. ARCHIVOS:
   - Si tienes archivos nuevos en local, sincronizarlos a S3:
     aws s3 sync ./Documentacion_Personal/ s3://byc-documentos-bucket/media/Documentacion_Personal/ --recursive

5. DEPENDENCIAS:
   - Verificar que boto3 y django-storages estén instalados en el servidor

6. SERVICIOS:
   - Hacer collectstatic: python manage.py collectstatic
   - Reiniciar Gunicorn: sudo systemctl restart gunicorn
   - Reiniciar Nginx: sudo systemctl restart nginx

================================================================================
PASOS PARA CAMBIAR DE NUBE A LOCAL
================================================================================

1. CÓDIGO:
   - Aplicar todos los cambios mencionados arriba para LOCAL
   - Comentar 'storages' en INSTALLED_APPS o dejarlo (no afecta en local)
   - Actualizar modelos para NO usar OverwriteStorage()
   - Agregar configuración de media en urls.py para desarrollo

2. BASE DE DATOS:
   - Cambiar a SQLite en settings.py
   - Aplicar migraciones: python manage.py migrate
   - Crear superusuario si es necesario: python manage.py createsuperuser

3. ARCHIVOS:
   - Los archivos en Documentacion_Personal/ ya deberían estar en tu repo
   - Si necesitas descargar archivos de S3:
     aws s3 sync s3://byc-documentos-bucket/media/Documentacion_Personal/ ./Documentacion_Personal/ --recursive

4. SERVIDOR DE DESARROLLO:
   - No necesitas Gunicorn ni Nginx
   - Ejecutar: python manage.py runserver
   - Los archivos media se servirán automáticamente en desarrollo

================================================================================
NOTAS IMPORTANTES
================================================================================

1. NUNCA commitear credenciales de AWS al repositorio
2. Siempre hacer backup de la base de datos antes de cambios importantes
3. En producción, considerar usar variables de entorno para todas las credenciales
4. El archivo .gitignore debe incluir:
   - db.sqlite3
   - *.pyc
   - __pycache__/
   - staticfiles/
   - /Documentacion_Personal/ (si no quieres subir archivos locales)
   - .env

5. Para un flujo más profesional, considera usar:
   - Archivo settings_local.py para desarrollo
   - Archivo settings_production.py para producción
   - Importar el apropiado según una variable de entorno
